1. Project Brief and Index

TempControl is a WPF desktop application for operating and monitoring an oven chamber. It combines PLC polling, an observable in-memory PlcDataStore, SQLite temperature and recipe storage, live and historical graphing, manual controls, alarm history, CSV reporting, and PDF trend export.

The application targets net10.0-windows. App.xaml.cs loads runtime configuration, creates MainWindow, and starts the application shell.

Current operational rules

3. Application Working and Flow

Startup sequence

  1. App.OnStartup creates AuthorizationService.
  2. Configuration is loaded from the executable directory and validated.
  3. MainWindow creates MainViewModel.
  4. The shared PlcDataStore is created and restored from plc_state_cache.json.
  5. DatabaseService.Initialize creates/opens SQLite and ensures recipes.
  6. ModbusPollingService starts logging and PLC polling.
  7. Screen ViewModels are created and Home is selected.

7. UI Screens

Home

Purpose: Primary live operating view. Files: HomeView.xaml, HomeViewModel.cs. Shows temperatures, setpoints/output-related values, process state, timer, safety values, and alarms. RUN and STOP use RunSessionService. Safety values remain beside zone headings and are fed from configured DataStore mappings.

Manual

Purpose: Authorized manual operation. Files: ManualPage.xaml, ManualPageViewModel.cs. Handles setpoints, safety temperatures, blowers, heaters, manual/auto checks, protected registers, and actuator coils.

Process Parameters

Purpose: Recipe preview, explicit apply, and Supervisor editing. Files: SettingsView.xaml, SettingsViewModel.cs. The visible controls are the recipe dropdown, SELECT, Step 1/2 fields, safety, blower ON/OFF, Edit, and Set Recipe. Dropdown selection is preview-only; SELECT writes current numerical values. D329 is not used. The former green inline feedback line was removed.

PLC I/O

Purpose: Display configured digital input/output points. Files: PlcIoView.xaml, PlcIoViewModel.cs. Data comes from PlcDataStore.IoPoints.

Graph

Purpose: Live/history trends and PDF export. Files: GraphView.xaml, GraphViewModel.cs, GraphView.xaml.cs. Includes mode/date controls, zoom, horizontal scroll, ruler, VALUES drawer, and export.

Alarm History

Purpose: Active/cleared alarm review and acknowledgement. Files: AlarmHistoryView.xaml, AlarmHistoryViewModel.cs, AlarmHistoryService.cs.

Data Log

Purpose: CSV report export and logging/communication controls. Files: MenuView.xaml, MenuViewModel.cs. Export uses DatabaseService.ExportToCsv.

Readings

Purpose: Electrical readings. Files: EnergyReadingsView.xaml, EnergyReadingsViewModel.cs. Shows voltage, current, power, and zone-current values.

Authorization Dialog

Purpose: Existing modal login. Files: AuthorizationDialog.xaml(.cs). Credentials are validated by AuthorizationService; successful login starts or replaces the configured session.

Run Dialog

Purpose: Configure run folder, file name, interval, and auto-start. Files: RunDialogWindow.xaml(.cs). Default folder is C:\ovencycle_runs; last folder is stored in run_folder.txt.

Export Heading Dialog

Purpose: Request a PDF heading only during export. Files: ExportHeadingDialog.xaml(.cs). Blank input falls back to Temperature Trend Report.

8. PLC Communication Protocol

Transport

  • Active PLC is Slave 4 using Omron FINS/TCP.
  • Current source endpoint is 192.168.250.1:9600.
  • OmronFinsTcpTransport uses HslCommunication.
  • Basic Modbus TCP/RS485 and null transports also exist.
  • The shared active transport is reused for writes; no second connection is opened.

Polling groups connections, retries with backoff, reads configured registers/coils, and dispatches updates on the WPF dispatcher. A semaphore serializes reads and writes. ManualControlService converts numeric values to bounded ushort values and delegates writes. D329 is not used for recipe-selection feedback in the current implementation.
